A

Accessibility

Access is part of the build.

This site aims to make a technical story usable across devices, input methods, reading preferences, and visual conditions.

Approach

Designed toward WCAG 2.2 AA.

The project uses semantic HTML, a consistent heading structure, keyboard-operable controls, visible focus states, a skip link, text alternatives, responsive layouts, and reduced-motion support.

Charts include a text description and an expandable data table. Result states use labels and symbols alongside color. The light and dark themes are both designed to maintain readable contrast.

01

Keyboard

Navigation, theme controls, accordions, tabs, filters, and the simulator can be operated without a pointer.

02

Structure

Landmarks, page titles, heading order, labels, captions, and ARIA relationships provide a meaningful reading sequence.

03

Perception

Color is redundant, text can reflow, focus is visible, and animation respects prefers-reduced-motion.

04

Data

Interactive charts update their accessible descriptions and expose the same values in an HTML table.

Known limitations

Accessibility is tested, not declared once.

This portfolio build has been reviewed at common responsive widths and with automated checks. A production project should additionally include testing with multiple screen readers, browser zoom to 400%, voice control, representative users, translated content, and real low-bandwidth devices.

If you encounter a barrier, open an issue in the GitHub repository with the page, browser, assistive technology, and expected behavior.
